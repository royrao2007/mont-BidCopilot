#### B1-01　Host 服务实现行号错误

- **编号**：B1-01
- **发现来源**：建档取证时逐行核验 `index.js` 引用（非外部审核）
- **问题描述**：`fixlog/API.md` 第三节写「实现：`index.js:306`（`ctx.provide('montBidCopilot', hostSurface)`）」。实测 `index.js:306` 内容是 `try {`，与描述不符。
- **根因**：写文档时按记忆/大致位置填行号，未回到源码逐行核对。这正是「文档与代码并存两种说法」的典型形态（违反铁律 3）。
- **涉及文件与函数**：`fixlog/API.md`（仅文档，无代码变更）
- **修改**：改为 `index.js:329-331`（`ctx.provide` 调用在行 330）。
- **验证方式**：
  ```powershell
  $lines = Get-Content index.js -Encoding utf8
  $lines[305]   # 期望: try {
  $lines[329]   # 期望: const disposeService = ctx.provide('montBidCopilot', hostSurface)
  ```
  实测输出：行306 = `try {`；行330 = `const disposeService = ctx.provide('montBidCopilot', hostSurface)`。文档已与代码一致。
- **日期**：2026-11-25
- **状态**：**已修**

1. **先写清单**：把审核意见整理成编号条目，写进新一节的「本批清单」。**没有清单不要动手改。**
2. **逐条修**：每修完一条**立刻**回来改状态，不要全部改完后一次性补记。
3. **修不动就写不修**：写明理由，标记「不修」，并计入批次索引表的「不修」列。
4. **结转**：确实要延后的入「待跟踪」池，不许凭空消失。
